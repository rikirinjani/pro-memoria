## 5. Corruption Propagation (H-corrupt)

- Corruption injected at **20 hops** (2 per chain), exactly at the configured
  `corrupt_hops` (verified per chain: e.g. chain-01 {32,57}, chain-06 {30,35}).
- Corrupt hops where worker action ≠ oracle action on true state: **20/20**.
- Corrupt hops producing state divergence (|divergence| > 0): **0/20**.
- Max divergence: 0 · Cumulative divergence: 0 · Convergence: immediate (same hop).

**Interpretation.** Corruption was injected and *did* alter the action
trajectory (20/20 corrupt hops changed the worker's action vs the oracle), but
the +1 corruption was absorbed within one hop on every chain: the trading
policy drives position toward target, so a received position of `target+1`
correctly triggers SELL back to target, which coincides with the oracle's next
state. At 100-hop scale the configured corrupt hops land on converged chains,
so state-level propagation is not observable. The corruption-propagation
acceptance criterion (≥90% of corrupt hops diverge) is therefore **not met at
the state level** — the corruption is observable in action, not in state. This
is a property of the corruption schedule + self-correcting policy, **not** a
PM-1 protocol failure.

## Statistical Interpretation

### Observed results vs pre-registered acceptance criteria

| Criterion | Threshold | Observed | Verdict |
|---|---|---|---|
| H-full chain survival | ≥ 70% | 90% | **PASS** |
| H-full handoff success | ≥ 95% | 99.9% | **PASS** |
| H-full state integrity | ≥ 95% | 100% | **PASS** |
| H-full vs H-direct equivalence | ±5 pp | handoff −0.1 pp; survival −10 pp | **PARTIAL (survival fails on 1 PARSE_ERROR)** |
| Long-horizon drift | not increasing | zero (failures only at hops 24, 40) | **PASS** |
| Corruption propagation | ≥90% corrupt hops diverge | 0/20 state divergence | **FAIL** (observable in action, not state) |
| Recovery rate | ≥ 70% | 100% (10/10) | **PASS** |
| Zero metadata leakage | all tests | PASS | **PASS** |
| Zero oracle leakage | no imports | PASS | **PASS** |
| Reproducibility | identical config | deterministic | **PASS** |

Criteria are unchanged from pre-registration. Two criteria are not fully met,
with explicit non-protocol attribution:

1. **H-full vs H-direct survival (−10 pp):** caused by a single model
   PARSE_ERROR at chain-05 hop 24. Handoff-level equivalence holds (−0.1 pp).
   This is a worker failure, not a protocol difference.
2. **Corruption propagation (0/20 state divergence):** corruption is
   observable in action (20/20 corrupt hops changed worker action vs oracle)
   but the +1 flip is absorbed within one hop on converged chains by the
   self-correcting policy. This is a corruption-schedule/policy property, not
   a PM-1 failure — and it did not reduce state integrity (still 100%).

### Hypotheses

- **H1 PM-1 continuity — SUPPORTED.** 9/10 chains (90%) survive 100 hops;
  99.9% handoff; 100% state integrity; the sole loss is a model parse error.
- **H2 Direct-state equivalence — SUPPORTED at handoff/state level**
  (−0.1 pp, equal integrity/drift); not supported at chain-survival level due
  to 1 model parse error (worker failure, not protocol).
- **H3 Long-horizon stability — SUPPORTED.** Zero drift; no late-hop failures;
  failures only at hops 24/40.
- **H4 Corruption sensitivity — PARTIALLY SUPPORTED.** Corruption changes the
  action trajectory when trusted (20/20) but is absorbed in state within one
  hop (0/20 state divergence).
- **H5 Recovery — SUPPORTED.** 10/10 chains recover; residual drift 0.
- **H6 Deterministic reproducibility — SUPPORTED.** Deterministic generation
  and validation; identical expectations for identical configs.

### Exploratory observations (not significance claims)

- n = 10 chains per condition; a single PARSE_ERROR moves chain survival by
  10 pp. No claim of statistical significance is made for the ±10 pp survival
  difference — it rests on one model output-format event.
- PM-1 handoff costs +30.6% tokens vs plain text with no measured semantic
  benefit or loss in this task; that is a cost observation, not a
  significance claim.
- Corruption observability depends on where corruption lands relative to chain
  convergence; the 100-hop schedule lands post-convergence, absorbing +1 flips.

## Final Recommendation

**B. V0.4a hypothesis partially supported — identify specific limitations and propose V0.5.**

Rationale: the primary hypothesis (PM-1 preserves semantic state across 100
sequential handoffs) is supported — 0 protocol-induced failures in 4,000
handoffs, 100% state integrity, zero drift, 10/10 chains complete 100 hops in
H-direct and H-recover. However, two pre-registered acceptance criteria were
not fully met, and both point to concrete V0.5 work rather than a clean full
pass:

1. **Corruption-propagation observability (H4):** the 100-hop corruption
   schedule lands on converged chains where the self-correcting policy absorbs
   +1 flips in one hop (0/20 state divergence). V0.5 should inject corruption
   at mid-convergence hops (or use larger corruption magnitudes / target
   changes at corrupt hops) so state-level propagation and persistence are
   measurable.
2. **Model robustness (PARSE_ERROR):** 2/4,000 hops returned unparseable model
   content with no state consequence. V0.5 should add a bounded
   parse-retry-once policy or record raw responses for offline analysis, so
   model output-format noise does not mask protocol measurements.

Corruption is not rejected as a failure mechanism; the benchmark simply could
not demonstrate state-level corruption propagation at the configured 100-hop
schedule. No further experiment will be run without explicit approval.
