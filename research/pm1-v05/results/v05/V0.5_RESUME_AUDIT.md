## 2. Defects Discovered (reported per stopping rules)

### D1 — BLOCKING: exception path references undefined `HandoffOutput`
`lib/v05a_chain.py` `run_v05a_chain()` except-branch constructs
`HandoffOutput(...)` but the module does not import it. When the provider
returned HTTP 402 (credit exhaustion) on the first call of horizon 250, the
exception handler itself raised `NameError`, crashing the run without
recording the failed hop or checkpointing. This must be fixed before resume
so that any API error is recorded per the V0.5 failure taxonomy instead of
killing the process. Fix: add `HandoffOutput` to the `lib.v05a_worker`
imports in `lib/v05a_chain.py`. This does NOT change any experimental
parameter (error-path only).

### D2 — NON-BLOCKING: `trial` not persisted per hop
Per-hop records omit the trial number (schema gap vs registered spec section
4). Trials are recoverable positionally in natural order (each H-hop block =
one trial) and were verified (exactly 3 per unit). Recommendation: keep the
current schema for consistency between the completed portion and the resumed
portion; document the limitation. Alternatively, enrich remaining records with
trial — decision left to authorization.

## 3. Why the crash happened (attribution)

- The HTTP 402 is a **provider/billing interruption** (DeepSeek credit
  exhaustion) — an execution interruption, not a change to the experimental
  design and not a model failure of the benchmark.
- The subsequent NameError is an **implementation defect** in the error path
  (D1) that masked the 402.
- **Zero completed experimental records were lost or corrupted** — horizon 250
  had not yet persisted anything when the process died.

## 6. D1 Resolution (addendum)

### Classification: **B — Contained**

- **Root cause:** `lib/v05a_chain.py` `run_v05a_chain()` except-branch (lines
  226-233) constructs `HandoffOutput(...)` but the module did not import it.
  Triggered only when `worker.run()` raises (API HTTP error, retry exhaustion,
  network failure, empty content after retries). A successful call never
  enters the except branch.
- **Impact:** crash-on-error instead of recording a PARSE_ERROR hop. No effect
  on successful calls, checkpoint persistence (atomic at horizon end), resume
  logic (skips completed horizons), token accounting, hop records, final
  aggregation. No duplicated/lost completed calls, no corrupted checkpoint, no
  skipped units, no incorrect counts/classification/totals. The 11,100
  completed calls are valid (all succeeded with usage_available=True, none
  touched the except branch).
- **Minimum fix applied (error-path only, no experimental change):** added
  `HandoffOutput` to the `from lib.v05a_worker import (...)` block in
  `lib/v05a_chain.py`.
- **Offline verification:** a RaisingWorker (simulated HTTP 402) now produces
  `classification=PARSE_ERROR`, first_failed_hop=1, total_failures=5,
  chain_survived=False — the chain completes and records the failure instead
  of crashing.
- **Offline suite:** 251/251 tests pass after the fix. Zero API calls made
  during investigation/remediation.
- **No completed calls require re-running.** Resume point unchanged.
